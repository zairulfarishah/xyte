Different crew for each day of a multi-day site

Right now one site = one crew list, no dates. So a 3-day site shows the same people on all 3 days. The idea: keep the site as one record, but let each day carry its own PIC + crew. Click around below — the card, calendar and workload all update live.

What it takes to build

— one nullable column, everything else is UI 
-- one row per person PER DAY. null date = "all days" (old rows keep working)
alter table site_assignments
  add column if not exists work_date date;

-- stop the same person being added twice to the same day
create unique index if not exists site_assignments_uniq
  on site_assignments (site_id, member_id, coalesce(work_date, '1900-01-01'));

create index if not exists site_assignments_date_idx
  on site_assignments (work_date);
Backwards compatible: every existing row gets work_date = null, which the app reads as “this person is on all days”. Nothing breaks on day one.
  • Sites.jsx — the day tabs above, and handleSave writes one row per (member, day) instead of one row per member.
  • Calendar.jsx / CalendarTimeline.jsx — when drawing a date, pick assignments where work_date = that date OR is null.
  • Dashboard.jsx — “who is out today” and the WhatsApp blast use today’s crew only.
  • Team.jsx / Statistics.jsx — a person’s site count becomes a day count.
  • workload.js — charge each member their own days instead of the full site span.
  • Leave check — getLeaveConflict runs per day, so Aina on leave Wed only blocks Wed.
Reports and PDF export need no change — they list everyone who touched the site, which is still just all the rows for that site.
